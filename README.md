# 어디서 결제할까

결제할 곳과 금액을 입력하면, 거기서 할인을 주는 **카드사앱 · 핀테크앱을 모두 모아
실제로 깎이는 금액 순으로 줄을 세우고 1등을 추천**하는 한 장짜리 웹페이지입니다.

예) KREAM에서 20만원 결제 → 삼성카드 10,000원 · 토스 6,000원 · KB Pay 5,000원
→ **삼성카드 추천**

검색은 이름·영문·별칭·초성을 모두 받습니다 (`크림` `KREAM` `ㅋㄹ` 전부 같은 결과).

빌드 도구나 서버 없이 `index.html` 을 브라우저로 열면 바로 동작합니다.

## 목록에 없는 결제처도 비교됩니다

혜택 데이터는 두 층으로 되어 있습니다.

- **가맹점 전용** (`scope: "merchant"`) — KREAM · 쿠팡 · 스타벅스처럼 특정 가맹점에 붙은 제휴
- **업종 공통** (`scope: "category"`) — "패션·리셀 업종 2% 할인"처럼 업종 전체에 걸리는 혜택

그래서 등록된 결제처를 고르면 전용 제휴 + 업종 혜택을 함께 보여주고, 등록되지 않은 곳을
입력하면 업종만 고르는 것으로 바로 업종 혜택끼리 비교됩니다. 카드사 혜택 페이지가 대부분
업종 단위로 굴러가기 때문에, 결제처를 일일이 등록하지 않아도 답이 나옵니다.

## 현금성 결제는 빼고 비교합니다

머니 충전·선불 잔액으로 결제해야 받는 혜택(예: 카카오페이머니, 토스머니 결제)은 비교에서
제외합니다. 데이터에 `funding: "prepaid"` 를 달아 두면 자동으로 걸러지고, 값이 없으면
카드 결제로 봅니다.

## 왜 단순 할인율 비교가 아닌가

실제 혜택에는 할인율 말고도 조건이 붙습니다. 이 페이지는 그걸 모두 계산에 넣습니다.

| 조건 | 처리 방식 |
| --- | --- |
| 할인 한도 (`cap`) | `할인율 × 결제금액` 이 한도를 넘으면 한도까지만 인정하고 "한도 도달" 표시 |
| 최소 결제금액 (`minAmount`) | 미달이면 순위에서 빼고 "지금은 못 쓰는 혜택"에 사유와 함께 표시 |
| 정액 할인 (`fixed`) | 금액 그대로 인정 |
| 구간별 정액 (`tiered`) | 결제금액이 속한 구간의 할인액 적용 |
| 할인 vs 적립 | 둘 다 계산하되 금액이 같으면 즉시할인을 위로 |
| 월 한도 · 선착순 | 계산에는 넣지 않고 표시만 (앱에서 잔여 횟수 확인 필요) |
| 현금성 결제 (`funding: "prepaid"`) | 비교 대상에서 제외 |

그래서 "할인율 1등"과 "실제로 가장 많이 깎이는 앱"이 다를 수 있고, 금액대에 따라 1등이
바뀝니다. 하단 그래프가 그 교차점("3만원 이상부터는 카카오페이가 유리")을 보여줍니다.

## 혜택 자동 갱신

혜택은 매달 바뀌고, 며칠만 열리는 게릴라성 혜택도 있습니다. 그래서 수집을 붙였습니다.

```
tools/collect.mjs  →  data/feed.js  →  페이지가 열릴 때마다 읽음
      ↑                    ↑
 data/sources.json    GitHub Actions 가 하루 네 번 갱신
```

페이지는 열릴 때마다 `data/feed.js` 를 읽어 번들 데이터 위에 덮어씁니다. 헤더에 마지막
수집 시각과 소스 성공/실패 개수가 표시됩니다.

### 브라우저가 카드사 사이트를 직접 읽을 수는 없습니다

페이지 자바스크립트가 카드사 페이지를 바로 가져오는 건 불가능합니다. 카드사 도메인이
CORS 헤더를 주지 않아서 브라우저가 응답을 막고, 대부분 봇 요청에 503 을 돌려줍니다.
그래서 **수집은 서버(=GitHub Actions)에서 돌리고, 페이지는 그 결과 파일만 읽습니다.**
"열 때마다 갱신"은 이 방식으로 달성됩니다 — 페이지는 항상 최신 `feed.js` 를 읽고,
`feed.js` 는 6시간마다 새로 만들어집니다. 더 자주 원하면 워크플로의 cron 만 바꾸면 됩니다.

수집기는 단순 HTTP 요청이 아니라 헤드리스 크로미엄으로 페이지를 엽니다. 카드사 목록이
대부분 자바스크립트로 그려지기 때문입니다.

### LINK · 마이샵 · 하나PICK · 꾹 — 공통 목록만 가져옵니다

이 프로그램들은 두 층으로 되어 있습니다.

- **공통** — 이번 달 어떤 가맹점이 목록에 올라와 있고 할인율·한도가 얼마인지
- **개인** — 그중 누구에게 열리는지, 내가 켰는지

수집기는 **공통 층만** 가져옵니다. 개인 층은 로그인해야 알 수 있고, 카드사 계정
자격증명을 다루는 건 만들지 않았습니다. 그래서 페이지에는 공통 목록에서 온 혜택이
"자동 수집" 배지와 함께 순위에 들어가고, 그 아래 **"앱에서 직접 켜야 하는 혜택"**
섹션에 프로그램별 바로가기와 수집 상태(`수집 12건` / `로그인 필요` / `차단됨`)가
함께 표시됩니다. 결제 전에 앱에서 한 번 켜야 실제로 적용된다는 점은 변하지 않습니다.

확인해 보니 이 목록들은 정적 HTML 에 없고 전부 XHR 로 내려옵니다 (비로그인 상태의
LINK 페이지는 "총 0개의 혜택"만 보입니다). 그래서 수집기는 페이지를 브라우저로 띄운 뒤
**DOM 과 네트워크 JSON 응답을 함께** 봅니다.

| 프로그램 | 등록된 주소 | 비고 |
| --- | --- | --- |
| 삼성카드 LINK | 전체 LINK 혜택 페이지 | 목록이 XHR 로 내려옴 |
| 신한 마이샵 | 마이샵 소개 페이지 | 매월 1일 목록 교체 |
| 우리 꾹 | 혜택 서비스 페이지 | '담기' 전 목록은 공통 |
| 페이북 마이태그 | 마이태그 안내 페이지 | 월 단위 태그 교체 |
| 하나PICK | 혜택 메인 | 전용 주소 미확인 |
| KB Pay · 현대 · 롯데 | 미등록 | 공개 주소 확인 필요 |

### 수집 결과는 세 갈래입니다

- **structured** — 가맹점·할인율·한도까지 읽어낸 것. 순위 계산에 들어갑니다.
  번들에 없던 가맹점이면 **결제처가 자동으로 새로 생겨** 검색까지 됩니다
  (업종은 페이지에서 한 번 지정하면 업종 혜택까지 같이 비교합니다).
- **raw** — 제목·기간·링크만 건진 것. "요즘 뜬 혜택 공지"에 링크로만 띄우고
  금액 계산에는 넣지 않습니다. 잘못 읽은 숫자로 순위를 흔드는 것보다 낫습니다.
- **hints** — 혜택 목록처럼 생긴 JSON 응답의 경로와 필드명. 첫 수집에서 힌트가 나오면
  `data/sources.json` 에 `pick` 매핑을 적어 주면 됩니다. 다음 수집부터 structured 로 올라갑니다.

```jsonc
// data/sources.json — 힌트를 보고 매핑을 적는 예
"pick": {
  "match": "/api/link.json",          // 이 주소를 담은 응답만
  "path": "data.benefitList",         // 배열이 있는 경로
  "map": { "merchantName": "mchtNm", "rate": "dcRt",
           "cap": "maxDcAmt", "minAmount": "minPayAmt", "period": "prd" }
}
```

### 주소를 못 찾은 프로그램은

하나PICK · KB Pay · 현대카드 · 롯데카드는 공개 목록 주소를 아직 못 찾았습니다. 이 목록들은
앱과 모바일 웹이 XHR 로 받아 그리므로, 앱 트래픽에서 주소를 잡아야 합니다. 방법은
[docs/find-app-endpoints.md](docs/find-app-endpoints.md) 에 쉬운 순서대로 정리해 두었습니다
(웹 쪽 `--dump` → 앱 공유하기 → WebView 원격 디버깅 → 프록시 캡처 → APK 정적 분석).

캡처한 HAR 은 손으로 옮길 필요 없습니다.

```bash
node tools/from-har.mjs capture.har --write samsung-link
```

혜택 목록처럼 생긴 JSON 응답을 점수순으로 찾아 `pick` 매핑까지 만들어 `sources.json` 에 넣습니다.

### 직접 돌려보기

```bash
npm install
npx playwright install chromium
npm run collect                      # 전체 수집 → data/feed.js
node tools/collect.mjs --only samsung # 특정 소스만
node tools/collect.mjs --dump         # 받은 JSON 응답을 tools/captures/ 에 저장
node tools/collect.mjs --selftest     # 네트워크 없이 DOM·XHR·힌트 세 경로 점검
```

소스를 추가하려면 `data/sources.json` 에 넣으면 됩니다. `programs` 는 LINK 처럼
"공통 목록은 공개, 적용은 개인화"인 프로그램, `public` 은 통째로 공개된 이벤트·쿠폰
목록입니다. 수집 결과는 소스별로 `ok / empty / login-required / blocked / no-url / error`
상태가 남고, 그대로 페이지에 반영됩니다.

## 구조

```
index.html            화면
assets/style.css      스타일 (라이트/다크 자동)
assets/app.js         할인 계산 · 순위 · 그래프 · 피드 병합
data/benefits.js      기본 혜택 데이터  ← 평소 고칠 곳
data/sources.json     수집 대상 주소록  ← 혜택 페이지 주소를 여기에 모읍니다
data/feed.js          자동 수집 결과 (생성 파일, 직접 수정 금지)
tools/collect.mjs     수집기 (헤드리스 크로미엄)
tools/from-har.mjs    앱 캡처(HAR) → pick 매핑 생성
docs/find-app-endpoints.md   앱에서 혜택 목록 주소 찾는 방법
.github/workflows/refresh-benefits.yml   6시간마다 수집 → 커밋
```

## 혜택 추가·수정하기

`data/benefits.js` 의 `benefits` 배열에 한 줄 추가하면 끝입니다.

```js
// 가맹점 전용 · 할인율 + 한도형
{ scope: "merchant", merchant: "kream", app: "toss", kind: "rate", rate: 0.03, cap: 10000,
  minAmount: 50000, benefitType: "할인", condition: "KREAM 결제수단에 토스페이 연결",
  monthlyCap: "월 1회" },

// 업종 공통 · 정액형
{ scope: "category", category: "delivery", app: "kbpay", kind: "fixed", amount: 2000,
  minAmount: 20000, benefitType: "할인", condition: "KB Pay 배달 쿠폰 받고 결제" },

// 구간별 정액형
{ scope: "category", category: "grocery", app: "samsung", kind: "tiered", minAmount: 50000,
  tiers: [{ min: 50000, amount: 3000 }, { min: 100000, amount: 7000 }],
  benefitType: "할인", condition: "삼성카드 앱 대형마트 쿠폰 등록" },
```

결제처나 앱, 업종을 새로 추가할 때는 같은 파일의 `merchants` / `apps` / `categories` 에
항목을 먼저 넣고 그 `id` 를 혜택에서 참조하면 됩니다. `aliases` 에 별칭("배민", "쓱닷컴")을
넣으면 그 말로도 검색됩니다.

## 지금 담긴 데이터에 대해

**들어 있는 수치는 구조를 보여주기 위한 예시입니다.** 카드사·핀테크 혜택은 매달, 때로는
주 단위로 바뀌고 선착순으로 조기 종료되기도 합니다. 실제로 쓰려면 각 앱의 혜택 탭을 보고
`data/benefits.js` 를 갱신한 뒤 `updatedAt` 날짜를 바꿔 주세요. 화면 오른쪽 위에 그 날짜가
"데이터 기준"으로 표시됩니다.
